## In short

One week. That's how long it took to go from a blank page to a product in production.

- **Time saved.** Our estimate: about a year for a team without AI, about three months with AI agents set loose with no plan and no rules. The product was running after one week.
- **A product you can rely on.** Every feature is checked by automated tests. The product can evolve without each change putting the rest at risk.
- **A product linked to what already exists.** It runs on its own, and it talks directly to the client's CRM.
- **Sensitive documents protected.** They are anonymized before the AI processes them, and each client company only sees its own data.

## How we made it possible

Speed doesn't come from the AI writing the code. It comes from the method around it.

### 1. The right goal, before a single line of code

First, we asked the uncomfortable questions.

Business: what is this software for? Should it cut costs, save time, automate a whole process? Or become the single point every business request goes through, gathered on a dashboard that assigns each job?

Technical: which core features, where to host it, how will other software and other AI agents plug into it?

Every answer ruled options out. In the end, one goal was left, and a short list of what the first version had to do.

### 2. A crystal-clear plan

We broke the software into bricks, each small enough to be built and tested on its own. Then we refined the plan, again and again.

We build that plan with AI, but we don't hand it over. We check what it proposes, then we check again. We ask questions. We look for the flaw. One rule drives everything else: **we only let the AI code once its words paint the right picture in our heads.**

### 3. Rules and tests before the AI starts

An AI agent codes as well as the frame you give it. Before launching it, we wrote its rules: how to write the code, how to structure the project, how to work day to day.

And we put tests first: for each feature, the test that checks it is written before the code. A feature only exists once its test passes.

### 4. A human review at every step

The AI built the product brick by brick. We reviewed every step before moving to the next.

### 5. Make it work, then make it beautiful

Our motto on this project: *make it work, make it beautiful*. The product worked on Friday, November 6. The same day, we started on the user experience and the finishing touches.

## For technical teams

The same deliverables, by their real names:

- **Multi-tenant authentication**: several clients on one instance, each isolated in its own data.
- **A graphRAG dictionary**: the domain vocabulary and the links between terms, stored as a graph, which the agent consults to interpret documents.
- **An autonomous agentic workflow**: information extraction, anonymization, a call to the language model, document reconstruction, direct editing, PDF generation.
- **Analytics**: jobs, time spent, logs and telemetry.
- **An API connection** to the CRM, and deployment as a standalone app and as a microservice.
- **Technical scoping** also raised the question of an API, or an MCP server (a standard connector that lets other AI agents plug into the product).
- **Test-driven development (TDD)**: when an agent changes the code later, the tests catch regressions before anything goes live.
- **Execution**: Claude Fable acted as the orchestrator. For each brick of the plan, it launched Claude Opus 5.5 sub-agents set to high reasoning effort.
